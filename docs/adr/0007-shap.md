# ADR 0007: SHAP explanations

- Status: accepted
- Date: 2026-11-17

## Context

A bank cannot act on a fraud score alone. Analysts need to know why a transaction was flagged
to review it quickly, and model risk teams need to show which inputs drive the model.

## Decision

- Use SHAP values, which split each prediction into additive feature contributions.
- Pick the explainer per model type:
  - XGBoost: exact `TreeExplainer`, in log-odds.
  - Logistic regression: exact `LinearExplainer`, in log-odds.
  - SVM and Keras network: model-agnostic permutation explainer on the fraud probability,
    with a capped sample (100 legitimate rows plus all test frauds, 50 background rows),
    because its cost grows with features x background size per row.
- Sum the sine and cosine time features into one `time_of_day` contribution so reasons read
  naturally.
- Produce two outputs from `fraud-explain`: global importance (mean absolute SHAP value and a
  chart) and the top three reasons for the highest-scoring test transactions. The same
  `top_reasons` function will feed the API response in phase 2.
- `shap` and `matplotlib` are an optional `explain` extra.

## Consequences

- Units differ by method (log-odds versus probability), so importance values are compared
  within a model, not across models; the report records the units.
- V1 to V28 are anonymised PCA components, so explanations show which components matter but
  cannot be translated into business terms such as merchant or country. Only `Amount` and
  `time_of_day` are directly interpretable.
- SHAP shows what the model uses, not causation.
